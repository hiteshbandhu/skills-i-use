# Workflows — Price AI products

## Workflow A — Define value

### Steps

1. Ask what the **customer perceives**, not internal metrics [src-001 @ 6:35].
2. Classify: automation, augmentation, enhanced service, improved results [src-001 @ 7:23].
3. Benchmark willingness-to-pay against outcome (e.g. decks not API calls) [src-001 @ 2:50].

### Deliverables

- [ ] One-page value statement per persona

---

## Workflow B — Charge metric

### Steps

1. **Consumption** — aligns to provider cost (infra/API) [src-001 @ 9:19].
2. **Workflow** — images, docs, sessions [src-001 @ 9:34].
3. **Outcome** — hires, tickets resolved, leads [src-001 @ 9:46].
4. Balance implementability vs value alignment [src-001 @ 10:19].

### Deliverables

- [ ] Primary + fallback metric with attribution plan

---

## Workflow C — Pricing model

### Steps

1. Reject pure subscription or pure usage for most AI SKUs [src-001 @ 2:06].
2. Default **hybrid**: base fee + scaling usage [src-001 @ 12:34].
3. Package as **credits** for stable customer UX [src-001 @ 11:09].
4. Remap credit weights under hood as features commoditize [src-001 @ 19:37].

### Deliverables

- [ ] Plan grid (good/better/best) + overage rules

---

## Workflow D — Guardrails

### Steps

1. Usage caps after included credits [src-001 @ 13:55].
2. Notifications at 50/70/90% [src-001 @ 14:23].
3. Rate limits against runaway code [src-001 @ 14:56].
4. Principle: fair, simple, no surprise bills [src-001 @ 13:45].

### Deliverables

- [ ] Customer-facing billing UX copy + enforcement rules

---

## Workflow E — Iterate

### Steps

1. Treat first price as hypothesis [src-001 @ 3:50].
2. Hypergrowth teams change pricing 3+ times / 2 years [src-001 @ 4:25].
3. Interview churned/upgraded users; A/B price tests [src-001 @ 15:43].
4. Billing stack must support fast changes [src-001 @ 16:56].

### Deliverables

- [ ] 90-day pricing experiment calendar
